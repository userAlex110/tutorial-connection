# 通信协议规范 (Communication Protocol Spec) v1.0

> 本文档定义了在异性交往中建议使用的应用层通信协议。遵循本规范可显著降低丢包率、减少延迟并提高连接稳定性。

## 1. 协议概述

传统的理工男通信协议（基于纯逻辑的 `Logic-Over-IP`）在处理情感数据时存在严重缺陷。本规范引入了 **情感层 (Emotion Layer)**，位于逻辑层之上，应用层之下。

### 1.1 协议栈结构

先说痛点：v1.0 的链路是「物理层 → 语言层 → 逻辑层 → 解决方案层」。情绪数据没被处理就被推向逻辑层，常见结果是对方感受不到被理解，从而直接丢包。

| 层级 | v1.0 默认操作 | v2.0 推荐操作 | 风险/收益 |
| :--- | :--- | :--- | :--- |
| Layer 4 | 上来就给方案 | **共情层 (Empathy)** → 判断是否需要方案 | 直接给方案易触发“没被理解”；先共情能降丢包率 |
| Layer 3 | 不加判断就讲逻辑 | 只有拿到情绪 ACK 后才启用逻辑 | 未经情绪授权的逻辑=噪声；ACK 后逻辑才被接收 |
| Layer 2 | 机械表达 | 语气/词汇随情绪收敛 | 语气不对等于误码；匹配情绪可降误码率 |
| Layer 1 | 声音/文字/肢体默认输出 | 先选择对方可接受的载体（语音/文字/陪伴） | 错载体易被视为打扰；对方偏好载体可提高带宽 |

**核心变更**：入站链路必须先过共情层，拿到 `ACK` 才能放行到逻辑层；出站链路也由共情层包装语气后再发出，避免“直接抛解决方案”导致的拥塞与丢包。

## 2. 握手协议 (Handshake Protocol)

建立连接是通信的第一步。

### 2.1 SYN (开启话题)
不要发送空包或无效包。

- **Bad Request (400)**: "在吗？" (Payload 为空，浪费带宽)
- **Bad Request (400)**: "吃了吗？" (低价值轮询)
- **OK (200)**: "刚才看到这个[图片/视频/新闻]，觉得你会感兴趣..." (携带有效 Payload)

### 2.2 SYN-ACK (响应话题)
当收到对方的 SYN 包时，必须在 `TIMEOUT` 时间内响应。

- **延迟策略**：秒回显得 `Idle` 资源过多（无所事事），隔天回显得 `Latency` 太高（不在乎）。建议根据对方的 `RTT` (往返时间) 动态调整你的响应时间。

## 3. 数据传输规范 (Data Transfer)

### 3.1 流量控制 (Flow Control)
避免 **单工广播 (Simplex Broadcasting)**。

- **现象**：你一个人一直在说自己感兴趣的话题（比如 Rust 语言的内存安全），对方只能回 "嗯"、"哦"。
- **警告**：检测到 `Buffer Overflow`。对方接收缓冲区已满，继续发送会导致丢包。
- **修正**：启用 **滑动窗口 (Sliding Window)** 机制。每发送一段信息，必须等待对方的 `ACK`（反馈），并根据对方的反馈长度调整下一次发送的窗口大小。

### 3.2 拥塞控制 (Congestion Control)
当发现对方回复变慢、字数变少时，触发拥塞避免算法。

1.  **慢启动 (Slow Start)**：减少发送频率，降低话题密度。
2.  **拥塞避免 (Congestion Avoidance)**：切换到轻松、低负载的话题（如美食、宠物）。
3.  **快速恢复 (Fast Recovery)**：如果对方重新活跃，再逐步增加话题深度。

## 4. 错误处理 (Error Handling)

### 4.1 常见错误代码

| Code | Error Message | Description | Solution |
| :--- | :--- | :--- | :--- |
| **401** | `Unauthorized` | 查户口式提问（"你多大？"、"住哪？"） | 停止越权访问，先通过分享自己获取信任令牌 (Token)。 |
| **403** | `Forbidden` | 强行邀约或肢体接触 | 立即回滚操作，道歉并冷却 CD。 |
| **404** | `Topic Not Found` | 聊了对方完全不感兴趣的话题 | 切换路由，寻找共同话题。 |
| **500** | `Internal Server Error` | 你情绪失控或表现出极度不自信 | 重启自身服务 (调整心态)，暂停通信。 |
| **503** | `Service Unavailable` | 对方正在忙，回复 "我去洗澡了" | 停止请求，等待对方主动重连。 |

### 4.2 异常捕获示例

**场景**：她抱怨 "同事真讨厌"。

**错误处理 (Crash)**：
```javascript
// 逻辑层直接介入
if (colleague.isAnnoying()) {
    suggest("Don't talk to him"); // 试图解决问题
}
// Result: Uncaught ReferenceError: Emotion is not defined.
```

**正确处理 (Try-Catch)**：
```javascript
try {
    listen(her_complaint);
} catch (EmotionException e) {
    // 捕获情绪异常
    empathy.validate(e); // "那是挺烦人的"
    empathy.support(e);  // "你一定受委屈了"
    
    if (she.asksForAdvice()) {
        logic.provideSolution(); // 只有在显式请求时才调用逻辑层
    }
}
```

## 5. 安全性 (Security)

- **加密通信**：不要在群里（公网）讨论私密话题，建立 P2P 私聊通道。
- **防火墙**：保护好自己的边界。不要为了讨好对方而开放所有端口（无底线妥协）。一个安全性好的服务器（有原则的男生）反而更具吸引力。

## 6. 总结

优秀的通信不仅仅是交换比特位，更是交换能量。
遵循本规范，你将从一个 **"只读不回"** 的终端，升级为一个 **"高可用、高并发、低延迟"** 的优质节点。
